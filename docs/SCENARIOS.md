# 시나리오 재현 절차와 실측 결과

각 시나리오를 **공격 → 로그 수집 → 탐지 → n8n 자동 대응(·AI-XDR 판정) → (승인) 차단 → 복구** 순서로 `scripts/scenario.py` 가 실행하고 시간을 잽니다. 결과는 `docs/results/*.json` 에 원본이 남습니다.

- 측정일: 2026-11-10, MacBook(Apple 칩, Docker 메모리 약 8GB), 이 저장소 구성 그대로. 시간은 모두 **공격 시작을 0초로 한 경과 시간**입니다.
- 사전 조건: `./scripts/up.sh` 완료, `./scripts/verify.sh` 통과. 각 시나리오는 시작 때 공격 PC(192.168.3.11) 차단을 풀고, 끝날 때도 풉니다(복구).
- 같은 명령을 다시 실행하면 같은 흐름이 재현됩니다(시간은 ±수 초 달라질 수 있음).

## 측정 방법과 한계

- Graylog 규칙 발동 시각은 Graylog 이벤트 API 의 타임스탬프, 알림 DB 적재는 `security_incident_alerts` 에 새 행이 생긴 시각(2초 간격 확인)입니다.
- AI-XDR 평가는 n8n 이 1분 단위로 이벤트를 모은 뒤 Groq 으로 판정하므로 약 40~120초가 걸립니다(`GROQ_API_KEY` 가 없으면 내장 판정).
- 승인→차단은 edge 가 5초마다 차단 목록을 동기화하는 구조입니다.
- Discord 전송은 n8n 실행 기록의 노드 성공 여부로 확인했고, Discord 앱 화면은 캡처하지 않았습니다(웹훅 주소 노출 방지).
- **하지 않은 것**: R1 의심 계정 잠금(관리자 승인 → 계정 잠금), 실제 Kali·Windows 에이전트, 진짜 pfSense 경유 트래픽.
