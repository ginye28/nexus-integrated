## 3. 시간이 더 있다면 개선하고 싶은 것

1. **진짜 pfSense 를 트래픽 경로에 연결** — 지금은 컨테이너 `edge` 가 대신하고 VM 은 따로 있습니다(Apple 칩 x86 에뮬레이션 + 공격 PC 출발지 IP 구분 문제).
2. **IP 자동 차단 예외·승인 정책을 설정으로 정리** — R1 승인 API 가 포털 dry-run 에서만 열려 `live` 와 동시에 못 쓰는 제약을 분리(팀 포털 코드 변경 필요).
3. **IP 자동 차단 예외 목록 정리** — 템플릿의 고정 목록(.10/.11/.14/.15)에 시연용 공격 PC(.11)가 들어 있어 자동 차단이 안 됩니다. 환경 변수로 분리하고 싶습니다.
4. 팀 시험 14개 실패를 **최신 코드에 맞게 고쳐 PR** 로 올리기.
5. 위협 점수 임계값(80점)과 주간/야간 정책을 데이터(실제 오탐률)로 조정.

## 4. 느낀 점

열심히 준비해서 우리가 만든 것을 다 보여주고 싶었지만 그러지 못해서 아쉬웠습니다. 그래도 팀 프로젝트 자체의 퀄리티는 괜찮다고 생각해서 좋았고, 팀원들과도 더 돈독해진 것 같아서 좋았습니다.

## 5. 프로젝트에서 배운 점 (기록에서 확인되는 것)

- 앱 레벨 방어는 양호했지만 네트워크 경계의 포트 노출이 더 큰 구멍이었던 경험(#2)에서, 점검은 층마다 따로가 아니라 같이 해야 한다는 것을 배웠습니다.
- 기능을 "켰다"와 "동작한다"는 다릅니다. 노드를 켜도 안전 스위치가 꺼져 있으면 아무 일도 일어나지 않았고(#12), 실제로 공격을 보내 결과를 재 보기 전에는 완료라고 말할 수 없다는 것을 확인했습니다.
- 같은 일을 팀원과 중복으로 했던 일(#7)을 계기로, 작업 전에 최신 상태와 담당을 확인하는 것이 협업의 첫 단계라고 느꼈습니다.
