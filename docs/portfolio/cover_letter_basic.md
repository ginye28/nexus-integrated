# 자기소개서 기본본 — 문제 해결 경험 (초안)

> 본인 경험·말투로 고쳐 쓰세요. 사실 근거는 괄호의 기록입니다.

## 문제 해결 경험 ① — "켜진 줄 알았는데 꺼져 있던" 상태 불일치를 한 곳으로 모은 경험 (PR #28)

사내 포털 보안 프로젝트에서 저는 팀장으로 공격 시연과 통합 점검을 맡았습니다. 보안모드를 껐다 켜도 결과가 일정하지 않은 문제를 발견했습니다(발견 경위는 본인 기억에 맞게 고치세요 — 커밋 메시지에는 '시연 녹화 때 ON/OFF 상태를 믿을 수 없었다'고 적혀 있습니다). 원인을 추적해 보니 웹 대시보드, 시연 스크립트, 토글 스크립트가 각자 설정 파일에만 값을 쓰고, 실행 중인 서버의 설정은 웹 토글만 바꾸고 있었습니다. 마지막에 쓴 경로가 말없이 덮어쓰는 구조라 감사 로그에도 남지 않았습니다.

저는 모드를 읽고 쓰는 함수를 하나로 정하고(서버 설정·환경변수·설정 파일을 동시에 갱신), 인증이 필요한 내부 API를 추가해 세 경로가 모두 같은 함수를 부르도록 바꿨습니다. 이 수정은 팀 저장소에 PR #28 로 병합됐습니다. 이후 네 가지 공격 시나리오를 ON/OFF 로 번갈아 실행해 결과가 일관됨을 표로 검증했습니다. 이 경험으로 "기능을 켰다"와 "실제로 동작한다"는 다르며, 상태의 기준을 한 곳에 두는 것이 신뢰성의 출발점이라는 것을 배웠습니다. (근거: 팀 저장소 PR #28, 활동일지 11/2)

## 문제 해결 경험 ② — 막힌 도구를 억지로 쓰지 않고 검증 후 대체한 경험

챗봇 앞단에 가드레일 라이브러리(NeMo Guardrails)를 붙이는 일을 맡았지만, 직접 설치해 보니 의존성이 80개에 이르고 사용 중인 Python 3.14 에서 네이티브 빌드가 실패했습니다. 일정에 쫓겨 우회 설치를 시도하는 대신, 필요한 기능(문장 중간 삽입형 무시 시도, 역할극식 탈옥 유도 차단)만 정리해 의존성 없는 경량 모듈로 구현했습니다. 기존 탐지(R2)는 그대로 두고 그 다음 단계에 연결했고, 공격 패턴 7종을 막으면서 정상 질문 8종은 막지 않는지 단위 테스트 20건으로 교차 확인했습니다. (근거: 활동일지 10/29)

## 문제 해결 경험 ③ — 기록에 없는 구멍을 직접 공격해 찾은 경험

기능 점검만으로는 놓칠 수 있다고 생각해 `nmap` 으로 방화벽 전체 포트를 직접 스캔했고, 포털 외에도 n8n·Graylog·DB·Ollama 관리 포트가 외부에 그대로 열려 있는 것을 발견했습니다. 담당 팀원 두 명에게 근거와 함께 조치를 요청했고, 앱 점검과 네트워크 점검을 함께 해야 한다는 의견을 팀에 남겼습니다. (근거: 활동일지 10/22)
